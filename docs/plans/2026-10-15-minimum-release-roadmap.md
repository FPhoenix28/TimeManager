# 最小发布路线图

日期：2026-10-15。依据：[开放事项](../OPEN_ISSUES.md)、[当前状态](../PROJECT_STATE.md)、[开源准备报告](../OPEN_SOURCE_READINESS_REPORT.md)及[Accessibility fallback 报告](../testing/ACCESSIBILITY_FALLBACK_REPORT.md)。这里的“阻止公开发布”指**向普通用户分发可安装 APK 或商店版本**。公开源码仓库是单独关口：迁移隔离、文档和 fresh-clone 构建已有证据，但候选仓库仍为 Private，须由所有者审查后决定是否公开；APK 签名和商店审批不阻止仅公开源码。

## 证据起点与执行顺序

- 已有：新独立仓库的 fresh-clone Debug/unsigned Release 构建、27 套件 / 125 个 Debug JVM 测试及 todo 迁移检查通过。迁移未做设备测试。此前主设备的部分深色竖屏 UI、导航和若干 Session 重入路径有设备证据。
- 当前未提交的 Accessibility fallback 改动另有 28 套件 / 141 个 host 测试通过；报告明确设备未连接，fallback、运行时连接状态和厂商后台行为仍待真机验收。只有该改动合入拟发布版本后，其 host 结果才属于该版本的证据。
- 先固定拟发布版本并完成下列 1、3、5 的主设备验收；发现阻断问题才修复并针对改动重测。随后完成 7 的分发审查。4、6 和 2 可在清楚标注限制的预览版之后继续验证；其中发现核心功能失效时升级为阻断项。设备操作遵守 [DEVICE_SAFETY.md](../../DEVICE_SAFETY.md)，不使用默认 `connectedDebugAndroidTest` 流程。

## 阻止可安装版本公开发布

### 1. 权限撤销矩阵（合并 Accessibility fallback 设备验收）

- **风险：** Usage/Overlay 撤销或 Accessibility 运行时断连时，提醒、计时、Daily 限额和权限提示可能与实际能力不符；Notification 撤销可能丢提醒。厂商将开关关闭与服务仅断连是不同情况。
- **已有证据：** Usage/Overlay/Notification/Accessibility 的降级规则已有实现和 host 测试；原有关键 Accessibility 关/开路径已验证。fallback 分支的 Session/Daily 软降级、状态区分和计时暂停已有 host 结果，尚无本轮设备结果。
- **验证方法：** 在拟发布包上逐项撤销 Usage、Overlay、Notification，覆盖提醒显示中撤销、首次提醒 HOME 捕获和权限通知的“查看”动作；再在主设备上区分系统开关已关与已开但运行时断连，观察 HOME、最近任务划走、锁屏、厂商后台处理及仅停止 TimeManager 后的状态。验证 fallback 同窗口倒计时与选择、计时暂停/恢复、Daily 超额重入及 +15；最后抽查原有 HOME/重入全能力路径。
- **依赖：** 固定拟发布代码，fallback 改动如纳入版本须先完成集成；使用本机实际包名和安全设备流程。与 3 共用重入场景。
- **完成判据：** 每种撤销/恢复状态的实际能力、页面提示和日志一致；Session/Daily 在 Usage+Overlay 可用时按设计软降级，Usage/Overlay 丢失时不继续假装拦截；恢复后无重复提醒或错误放行。记录版本、设备、操作、预期与实测及未能触发的场景。若有核心路径失败，修复后复测该路径。

### 3. 重入与优先级回归

- **风险：** 通知进入目标应用或多个干预同时触发时可能绕过限额、重复弹层，或错误消耗 Session 阶段。
- **已有证据：** 同阶段 gate 消耗、Continue/Stay Home、下一次 +8 分钟阶段和真实五分钟空闲重置已有设备证据；优先级和扩展逻辑有 host 回归。最新迁移无设备回归。
- **验证方法：** 在拟发布包上从目标应用通知进入，覆盖 Session、Daily、Focus、Deep 同时符合条件的组合；检查 `DEEP_FOCUS > FOCUS_BLOCK > DAILY_LIMIT > SESSION`，并在 Daily +15 前后重入，核对基础额度、有效额度及未展示的 Session 阶段。
- **依赖：** 1 的权限状态和 fallback 模式先明确；固定测试额度/阶段和拟发布版本。
- **完成判据：** 每次入口只显示最高优先级的有效干预；Daily 扩展生效且不修改基础额度；低优先级 Session 未展示时不推进阶段；通知入口没有绕过或重复 gate。只记录新增缺口，不重做已有证据充分的 gate/idle 全矩阵。

### 5. 来电场景

- **风险：** Deep Focus 遮住接听或通话界面，或通话结束后覆盖层不能正确恢复，会直接影响设备基本通信。
- **已有证据：** 代码保留系统/紧急界面例外；紧急 UI 检查不证明真实来电兼容。没有真实来电验收结论。
- **验证方法：** Deep Focus 生效时接收真实来电，观察来电、接听、通话中及挂断后的界面和覆盖层；记录前后台状态与恢复时间。
- **依赖：** 可控的第二个呼叫端、1 中已确认的 Overlay/Accessibility 状态和拟发布包。
- **完成判据：** 来电和通话操作可正常完成；覆盖层按设计让位并在结束后恢复，普通应用仍受 Deep Focus 约束；异常必须修复并重验后再分发。

### 7. 发布分发审查

- **风险：** 错误版本标识、未签名包、权限披露或素材权属不清会使公开二进制分发不可信或不可行；OS backup 与隐私说明不一致会误导用户。
- **已有证据：** 独立仓库历史和素材清理、许可证/NOTICE、fresh-clone Debug/unsigned Release 构建已记录；`versionName=1.0` 为旧元数据，尚无生产签名、商店政策认可或最终二进制审查。
- **验证方法：** 选定预览版版本号与签名/分发渠道；核对最终包的 applicationId、权限、app visibility、Accessibility 与 special-use 前台服务说明；逐项确认第三方视觉素材来源、Android backup 行为、隐私说明及发布说明与实际功能/限制相符。商店渠道另按该渠道实际审查结果记录。
- **依赖：** 1、3、5 的设备结论及拟发布版本固定；公开源码只需先完成所有者的仓库可见性审查，不等待签名/商店流程。
- **完成判据：** 分发包可按选定渠道安装、签名及版本信息一致；必要的权限、素材、备份和隐私披露均有可审阅记录；未取得渠道批准时不声称“商店已批准”。仅源码公开时明确没有发布安装包。

## 影响用户信任但可后置到预览版之后

### 4. 后台 todo 阶段

- **风险：** 04:00 跨日、20:00/23:00 提醒和通知点击在真实系统调度下可能延迟或漏达，用户会误以为待办状态可靠地实时同步。
- **已有证据：** Room 迁移和确定性的 host 调度测试已通过；WorkManager 本来就是可延迟任务，不保证精确时刻。真实后台阶段尚未完整观察。
- **验证方法：** 保留应用数据，在真实 04:00 边界及 20:00/23:00 阶段观察待办分组、提醒发出/去重、通知点击和 OS 延迟；记录触发与实际到达时间及后台条件。
- **依赖：** Notification 权限与 1 的状态记录；跨时段测试安排。
- **完成判据：** 日期归属、去重和点击落点正确；延迟符合“可延期提醒”的产品表述。若普遍不送达或点击错误，升级为分发阻断并修复；单纯延迟如实写入说明。

### 6. 跨 Android/厂商覆盖

- **风险：** 其他厂商的后台限制、UsageEvents 保留、启动提示或权限设置路径可能让主设备结论无法推广。
- **已有证据：** 主要设备证据集中在 vivo X200s / Android 16；受系统限制的 Debug Logcat 不能证明事件不存在。没有足够的跨厂商矩阵。
- **验证方法：** 在可取得的其他厂商/Android 版本设备上抽查首次授权、后台存活、事件/统计回填、通知入口和权限恢复；记录机型/系统版本、限制及可重复结果。
- **依赖：** 1、3 的主设备基准和可用测试设备。
- **完成判据：** 每个已测试环境有结果与适用范围；公开说明明确主要验证平台和未覆盖范围。发现普遍的数据丢失、错误拦截或无法恢复时升级为阻断项；不把单机结果写成全 Android 保证。

## 纯文档或体验优化

### 2. 响应式 UI 验证与修整

- **风险：** Light、大字体、真实横屏、独立对话框及 Session/Daily 待办摘要可能出现截断或遮挡，影响可读性和操作体验。
- **已有证据：** 共享响应式布局已有 host 处理和部分主设备深色竖屏观察；锁定竖屏后发送旋转命令不构成真实横屏证据。完整视觉矩阵未完成。
- **验证方法：** 在实际可进入的 Light/大字体/横屏配置中逐屏检查核心按钮、倒计时、对话框及待办摘要；保存可公开的泛化观察记录，必要时修整布局。
- **依赖：** 拟发布 UI、可切换的显示设置；临时设备设置按安全规则恢复。
- **完成判据：** 测过的配置中信息可读、按钮可达，未覆盖配置明确列出；只涉及间距/观感的问题可后置。若“继续/退出/接听”等核心操作不可达，立即升级为发布阻断，修复并在该配置复测。

发布说明还应写清已知限制：WorkManager 可能延迟、厂商后台行为未全覆盖、统计历史依赖系统保留，以及当前设备验证范围。这些说明随各项结果更新，不另外制造一轮 host/fresh-clone 构建任务，也不把已经验证的 Accessibility 开关路径重新登记为开放缺口。
